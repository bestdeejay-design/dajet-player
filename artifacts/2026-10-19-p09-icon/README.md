# P-09 — вердикт владельца по иконке плеера

**Дата:** 2026-10-19
**Владелец:** best (наблюдал две иконки бок о бок в Preview)
**Вердикт:** **принята иконка из `Icon/icon.swift`** (плита на всю канву + волна,
генерируется кодом при сборке). Иконка из PR #17 (`media/icon.mjs` →
`assets/AppIcon.icns`) — **отклонена**.

## Почему

Владелец смотрел два варианта рядом, оба 512×512 и оба же в записи 16 px:

| Файл | Что | Вердикт |
| --- | --- | --- |
| `icon-accepted-512.png` | иконка из `Icon/icon.swift` | ✅ «более-менее» → **принята** |
| `icon-accepted-16px.png` | она же, запись 16 px, увеличена | ✅ |
| `icon-pr17-rejected-512.png` | иконка PR #17 | ❌ отклонена |
| `icon-pr17-rejected-16px.png` | она же, запись 16 px, увеличена | ❌ |

### Важное уточнение: канон один, отличается рендерер

Проверено сверкой констант и точек: `Icon/icon.swift` и `media/icon.mjs` (PR #17)
рисуют **одну и ту же геометрию** — канва 1024, угол `0.2253 × 1024`, штрих **92**,
плита `#15181C` на всю канву, волна `#E8AE8C` по тем же точкам (`187.96,404.79` …
`512.00,512.00`). Отличие картинок — **рендерер и даунскейл**: AppKit против
`sharp`/Lanczos. Владелец выбрал рендер `Icon/icon.swift`. Он же даёт `.icns`
**и `Assets.car`** (Icon Composer doc для Dark/Tinted macOS 26), чего у `media/icon.mjs`
нет.

## Разница подходов (не только картинка)

| | Принятая (`Icon/icon.swift`) | Отклонённая (PR #17 `media/icon.mjs`) |
| --- | --- | --- |
| Источник | Swift-генератор, рисует при сборке | JS-генератор → готовый `assets/AppIcon.icns` в репо |
| Зависимости | ноль (AppKit/Foundation) | Node 20+ (`@napi-rs/canvas`, `sharp`) — только для пересборки |
| Результат | `.icns` **+ `Assets.car`** (Icon Composer doc для Dark/Tinted macOS 26) | только `.icns` |
| Ассет в репо | нет (генерится) | да (бинарник `AppIcon.icns`) |

## Что берём из PR #17 всё равно (не иконку)

Вердикт касается **только иконки**. Из PR #17 ценны и берутся:

- `media/check-icns.mjs` — проверяльщик `.icns` (записи 16/32, плита заполняет канву) — закрывает находку **F-1**;
- `assets/screenshots/*` — **нарисованные** Ареной; подлежат замене реальными снимками (у Арены нет Mac, у координатора есть);
- `assets/og-player-1200.jpg`, `assets/og-player-1080.jpg` — социальные карточки;
- `assets/header.svg`, `assets/footer.svg` — баннеры README;
- `media/fonts/Inter-*` (OFL), остальной `media/*.mjs`, `docs/BRAND.md`, README-правки;
- `media/icon.mjs` — **НЕ берём** (дублирует канон; иконка генерится `Icon/icon.swift`).

## Решение владельца: один генератор иконки — `Icon/icon.swift`

Раз канон один, генератор оставляем **один** — `Icon/icon.swift` (Swift, ноль
зависимостей, даёт `.icns` + `Assets.car`). Из PR #17 при cherry-pick **исключаются**:

- `media/icon.mjs`
- `assets/AppIcon.icns`, `assets/icon.svg`, `assets/icon-1024.png`, `assets/icon-16x16-enlarged.png`
- правка `build.sh`, копирующая `assets/AppIcon.icns` (иконку встраивает `Icon/icon.swift`)
- правки `README`/`docs/BRAND.md`, описывающие `media/icon.mjs` как источник иконки

`media/` в репо остаётся для **скриншотов, OG-карточек и баннеров**; `check-icns.mjs`
берём как проверяльщик `.icns` (записи 16/32) под принятую иконку.

## Дополнение: приёмка и доработка (2026-10-19, вечер)

Когда приёмка прогнала `media/check-icns.mjs` на **исходной** иконке `Icon/icon.swift`
(той, что владелец выбрал глазами), проверяльщик забраковал её:

```
ic13 256x256 plate=0.867 edge=0.44 ❌ MARGIN: the plate does not fill the canvas
ic10 1024x1024 plate=0.869 edge=0.30 ❌ MARGIN
+ ic04/ic05/info: could not decode   (11 entries, DEFECT)
```

Причина — не геометрия (плита идёт inset 0), а **рендер**: суперэллипс-полигон
хордами уходил внутрь, а антиалиасинг оставлял крайние пиксели полупрозрачными
(`alpha 236…254` вместо 255 у края); плюс `iconutil` дописывал legacy raw-bitmap
записи (`ic04`, `ic05`, `info`), которые современный reader не декодирует.

Иконку **доработали** (тот же канон, тот же генератор `Icon/icon.swift`):

1. плита **перекрывает** канву (overhang ~0.6 %) — собственный край ложится плотно;
2. один **master 1024**, малые размеры — его даунскейл (никакого `NSImage` round-trip);
3. генератор пишет **`.icns` сам**, PNG-only, 10 Apple-типов — без `iconutil`.

Итог: `node media/check-icns.mjs build/AppIcon.icns` →

```
10 entries, all clean          (edge=1.00 на всех записях, 16 px читается)
```

— наравне с эталоном Арены. Принята в `main` (приёмка `ff39b61`); PR #17 и #14 закрыты.

## Скриншоты: решение координатора

`assets/screenshots/*` остаются **нарисованными из канонической раскладки**
(`media/ui.mjs` воспроизводит метрики `Presentation.swift`: 548×284 и 232×441,
2× → 1096×568 и 464×882). Это детерминированно, воспроизводимо одной командой
(`node media/build.mjs`) и не требует живого десктопа/курсора; живые снимки дали бы
шумный фон и хуже читались в README. Финальная эстетическая оценка — за владельцем.
